# 后续开发里程碑

以下顺序优先保证声景的核心价值和可验收性，不继续堆叠没有用户结果的架构。一个里程碑达到验收条件后再进入下一个，并同步更新 `current-development-state.md`。

## 0. 新设备复现基线

目标：陌生开发者或 Agent 只依赖 Git 和文档恢复完整开发环境。

验收：

- 按 `docs/development/new-machine-setup.md` 从干净克隆完成 `npm ci`、`npm run doctor` 和 `npm run check`。
- Web 可以播放两个默认声景；Windows 或一个移动目标可以启动 Flutter 客户端。
- `git diff --check` 通过，资源同步后除预期生成文件外没有漂移。
- 当前 `main` 已推送到 canonical `origin`，新设备不依赖旧电脑未推送的提交。

## 1. 检索优先的自然语言纵切

目标：把产品最核心的“一句话”接到现有 63 份素材和 SceneRecipe，而不是先生成长音频。

最小调用链：

```text
描述
  -> Planner 提取环境、事件、媒介、空间和情绪
  -> Catalog Retrieval 只检索 approved 素材
  -> Recipe Builder 生成 SceneRecipe v1
  -> Validator 校验 schema、素材、片段和数值范围
  -> 客户端后台预载
  -> 完成通知，由用户决定是否切换
```

验收：

- 代表性提示词和无匹配提示词都进入自动测试，任何结果都只能引用目录中的稳定 ID。
- 无效配方在进入音频运行时前被拒绝，并返回用户可理解的恢复路径。
- 生成期间当前声景继续播放；完成后不自动切换。
- 后端不可用时，已下载素材、用户素材和默认声景继续离线运行。
- Agent、API 和客户端共同消费 `contracts/scene-recipe.v1.schema.json`，不建立第二套字段。

## 2. 内容质量与编排验收

目标：把“63 份素材”转化为明显有设计、有层次、无机械循环的声景，而不是继续只增加文件数量。

验收：

- 建立覆盖天气、水域、野生动物、空间、火、媒介和设备质感的代表性场景集。
- 每个候选场景记录语义匹配、层次、响度、事件密度、距离感和接缝评审。
- 连续声景执行至少 30 分钟的接缝、重复、计时漂移和堆叠检查。
- 失败素材或片段可以被单独替换，不需要重新渲染一条长音频。
- Web 精选只展示已通过内容验收的少量场景；完整素材与创建能力留在客户端。

## 3. 在线声音包

目标：避免把不断增长的素材全部永久塞进安装包，同时保留离线使用。

验收：

- 声音包清单包含版本、文件哈希、来源、许可证、大小和兼容的 schema 版本。
- 下载支持断点、校验、原子激活、失败恢复和版本回滚；当前播放不被下载抢占。
- 基础包和可选包边界经过体积与首用体验评审。
- 素材文件继续使用内容寻址；索引规模达到迁移条件时才把 `SoundscapeStateStore` 后端换成 Drift。
- 发布构建拒绝来源不完整、哈希错误或不可再分发的素材。

## 4. 真机和发布链路

目标：把“可开发运行”提升为可交付客户端。

验收：

- Android 与 iPhone 记录设备、系统版本、30 分钟以上播放、锁屏、来电、耳机、蓝牙、系统回收、发热和耗电结果。
- 完成正式包标识、签名、隐私说明、崩溃与性能观测、版本号和可回滚更新。
- 建立固定字体和稳定素材的关键界面截图回归，同时保留人工动效与听感验收。
- 明确仓库代码许可证；音频继续按逐文件许可证发布。

## 5. 同步、分享和导出

账号同步、跨设备用户片刻、分享链接和完整音频导出都在核心声景质量与发布稳定后推进。同步只保存配方、偏好和有权限的数据；用户私有音频默认不上传，导出也不能改变素材授权边界。
