# 仓库结构与依赖边界

## 目录职责

- `assets/` 是运行时静态资源的唯一入口。正式页面通过场景清单或明确路径消费这里的资源。
- `design/` 保存设计过程材料，包括生成提示词、方向板、质量参考和人工验收图；运行时代码不得依赖该目录。
- `prototypes/` 保存可运行、可替换、可丢弃的实验。原型可以读取 `assets/`，但不能成为产品事实或后端能力的证明。
- `docs/` 保存长期有效的架构说明和研究结论。临时验收日志与构建输出不属于文档。
- `tools/` 保存跨目录校验脚本，不放具体原型的构建工具。
- `.impeccable/` 只保存工具配置、决策答案和 surface brief；截图、日志与状态文件不提交。

## 权威来源

1. 产品定位和能力边界：`PRODUCT.md`。
2. 视觉语言与交互规则：`DESIGN.md`。
3. 静态资源元数据：`assets/catalog.json`。
4. 场景发现与槽位状态：`assets/scenes/index.json` 和各场景的 `scene.json`。
5. 当前日常界面验证：`prototypes/emotional-player/`。

## 依赖方向

```text
PRODUCT.md + DESIGN.md
          |
          v
       assets/ <--------- design/
          |
          v
     prototypes/
```

`design/` 负责产出和解释资源，但不进入运行时依赖；`prototypes/` 可以消费正式资源，不能反向成为资源清单的权威来源。

## 提交边界

- 产品定义和设计规范单独提交。
- 静态资源、资源清单、对应提示词和校验脚本作为一个完整边界提交。
- 探索原型与当前产品原型分开提交。
- `node_modules/`、`dist/`、临时截图和工具运行状态不进入历史。
